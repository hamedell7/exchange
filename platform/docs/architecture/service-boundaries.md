# Service Boundaries

## Identity

مالک حساب‌های کاربری مشتریان، شناسه هویتی، اعتبارنامه‌ها و چرخه عمر احراز هویت است؛ از جمله ثبت‌نام، تأیید هویت حساب، بازیابی اعتبارنامه و نشست‌های احراز هویت. مدل Domain و Eloquent این سرویس فقط در همین Bounded Context معتبرند.

شناسه کاربر که از Identity صادر می‌شود، در سرویس‌های دیگر فقط به‌عنوان یک شناسه خارجی و opaque استفاده می‌شود. هیچ سرویس دیگری User Entity، Eloquent Model، جدول حساب یا Credential مربوط به Identity را import یا query نمی‌کند.

## Wallet

مالک حساب‌های دارایی، دفتر کل، ثبت بدهکار/بستانکار، رزروها و مانده‌های مشتق‌شده از دفتر کل است.

Wallet مالک حساب کاربری نیست و نباید جدول محلی 'users'، رمز عبور، بازیابی رمز یا User Model مستقل داشته باشد. در صورت نیاز، فقط شناسه پایدار کاربر را به‌عنوان reference نگه می‌دارد.

اگر یک قابلیت خواندنی واقعاً به اطلاعات نمایشی کاربر نیاز داشته باشد، می‌توان در آینده یک Projection محدود و مخصوص همان نیاز تعریف کرد؛ این Projection جایگزین Identity نیست و نباید شامل Credential یا کل Aggregate کاربر باشد. تا زمانی که Query یا نیاز عملی مشخصی وجود ندارد، چنین Projectionی ساخته نمی‌شود.

## Trading

مالک بازارها، سفارش‌ها و معاملات است. Trading برای رزرو یا آزادسازی وجه از قرارداد Wallet استفاده می‌کند و نباید مستقیماً جداول آن را بخواند.

Trading نیز مالک حساب کاربری نیست و نباید جدول محلی 'users'، Credential، Password Reset یا User Model مستقل داشته باشد. شناسه کاربر در سفارش‌ها و فرایندهای معاملاتی فقط یک reference به شناسه صادرشده توسط Identity است.

اطلاعات نمایشی کاربر فقط در صورت وجود نیاز Query مشخص و با حداقل فیلدهای لازم می‌تواند به شکل Projection نگهداری شود؛ نه به‌صورت تکثیر User Aggregate یا اطلاعات احراز هویت.

## Gateway

مسئول ورود و مسیریابی درخواست‌هاست؛ مالک منطق دامنه یا حساب کاربری نیست. اعتبارسنجی هویت درخواست‌ها باید بر پایه قرارداد احراز هویت بین سرویس‌ها انجام شود؛ جزئیات این قرارداد و Adapter مربوطه پیش از پیاده‌سازی Authentication بین‌سرویسی تعیین خواهد شد.

## Sessionهای فریم‌ورک در Wallet و Trading

جدول 'sessions' که در این دو سرویس باقی می‌ماند صرفاً Storage عمومی Laravel برای HTTP session با تنظیم فعلی SESSION_DRIVER=database است. این جدول مالکیت حساب، Credential یا نشست احراز هویت Identity را به Wallet یا Trading منتقل نمی‌کند و Foreign Key به User ندارد.

## اصل استقلال

هر سرویس دیتابیس، Migration، استقرار و چرخه انتشار مستقل دارد. هیچ Foreign Key بین دیتابیس‌های سرویس‌ها وجود نخواهد داشت.

اصول مشترک مدل‌سازی، لایه‌بندی، Aggregateها، Repositoryها و تست‌ها در [راهنمای DDD پلتفرم](domain-driven-design.md) تعریف شده است.
