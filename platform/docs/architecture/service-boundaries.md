# Service Boundaries

## Identity

مالک حساب‌های کاربری مشتریان، شناسه هویتی، اعتبارنامه‌ها و چرخه عمر احراز هویت است. مدل داده و Eloquent این سرویس فقط در همین Bounded Context معتبرند.

شناسه کاربر در سرویس‌های دیگر فقط به‌عنوان یک شناسه خارجی و opaque استفاده می‌شود. هیچ سرویس دیگری User Model، جدول حساب یا Credential مربوط به Identity را import یا query نمی‌کند.

## Wallet

مالک حساب‌های دارایی، دفتر کل، ثبت بدهکار/بستانکار، رزروها و مانده‌های مشتق‌شده از دفتر کل است. Wallet مالک حساب کاربری نیست و فقط شناسه پایدار کاربر را به‌عنوان reference نگه می‌دارد.

## Trading

مالک بازارهای قابل معامله داخل Exchange، سفارش‌ها، معاملات و داده‌های Order Book خود Exchange است. Trading برای رزرو یا آزادسازی وجه از قرارداد Wallet استفاده می‌کند و نباید مستقیماً جداول آن را بخواند.

Trading مالک قیمت مرجع جهانی یا فهرست تحلیلی بازار جهانی نیست. در آینده قیمت آخرین معامله و بهترین سفارش خرید و فروش Exchange از خود Trading و Matching Engine تأمین خواهد شد.

## Market Data

مالک کاتالوگ عمومی دارایی‌های رمزارزی و داده مرجع بازار جهانی است؛ از جمله شناسه منبع خارجی، نام، نماد، نامک، لوگو، رتبه بازار و اطلاعات متادیتای Asset.

Market Data قیمت مرجع جهانی را از Provider بیرونی دریافت می‌کند. این داده با قیمت معاملات واقعی Exchange یکی نیست و نباید به‌عنوان قیمت قطعی سفارش یا اجرای معامله در Trading استفاده شود.

Market Data مالک سفارش‌ها، معاملات، موجودی یا حساب کاربر نیست. Trading نیز به دیتابیس Market Data دسترسی مستقیم ندارد؛ در صورت نیاز از API یا قرارداد Event استفاده می‌کند.

## Gateway

مسئول ورود و مسیریابی درخواست‌هاست؛ مالک منطق دامنه یا داده سرویس‌ها نیست. احراز هویت و مجوزدهی منابع باید در سرویس مالک دامنه انجام شود.

## اصل استقلال

هر سرویس دیتابیس، Migration، تنظیمات و چرخه انتشار مستقل دارد. هیچ Foreign Key بین دیتابیس‌های سرویس‌ها وجود نخواهد داشت.
